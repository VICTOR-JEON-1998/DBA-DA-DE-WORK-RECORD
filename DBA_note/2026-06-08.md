# Daily 학습

- SQL Server를 쓰면서 "데이터가 삭제되면 어떻게 되지?" 라는 질문을 처음 깊이 파고들었습니다.
- 오늘 학습한 내용을 정리해봤습니다.
- 📌 DELETE는 즉시 삭제가 아닙니다
- DELETE를 실행하면 행이 즉시 사라지지 않습니다. 행 헤더에 Ghost 플래그만 세우는 논리적 삭제가 먼저 일어나고, 실제 물리적 제거는 백그라운드의 Ghost Cleanup 스레드가 나중에 처리합니다. 스냅샷 트랜잭션이 활성화돼 있으면 이 정리가 지연되고, 그 사이 페이지 밀도가 떨어져 단편화로 이어질 수 있습니다.
- 📌 TRUNCATE와 DELETE는 구조부터 다릅니다
- DELETE는 행 단위 Ghost 마킹, TRUNCATE는 익스텐트 단위 즉시 해제입니다. 307GB 테이블에서 대량 삭제가 필요하다면 파티션 TRUNCATE 또는 SWITCH OUT이 Ghost Record 누적 없이 훨씬 효율적입니다.
- 📌 UPDATE는 디스크를 직접 건드리지 않습니다
- 변경이 발생하면 항상 트랜잭션 로그에 먼저 Before Image를 기록(WAL)하고, 그다음 버퍼풀의 페이지를 수정해 Dirty Page를 만듭니다. 실제 디스크 반영은 Checkpoint까지 미뤄집니다. 같은 페이지를 10번 수정해도 디스크 I/O는 최초 로드 1번뿐입니다.
- 📌 롤백은 로그의 역추적입니다
- ROLLBACK이 실행되면 트랜잭션 로그를 LSN 역순으로 읽으며 Before Image로 되돌립니다. 로그에는 File ID + Page ID + Slot ID 조합으로 정확히 어느 행을 바꿨는지 기록돼 있어 정확한 Undo가 가능합니다. 롤백 비용은 작업량에 비례하므로 대용량 배치 중간에 롤백이 걸리면 오히려 더 오래 걸릴 수 있습니다.
- 📌 GAM · SGAM · PFS · IAM — 공간 관리의 4총사
- SQL Server는 어느 익스텐트가 비었는지(GAM), 혼합 익스텐트 중 여유 있는 곳이 어딘지(SGAM), 각 페이지의 여유 공간이 얼마인지(PFS), 특정 테이블이 어떤 익스텐트를 쓰는지(IAM)를 별도 페이지로 추적합니다.
- 📌 페이지와 익스텐트는 역할이 다릅니다
- 페이지(8KB)는 I/O의 최소 단위, 익스텐트(64KB = 8페이지)는 공간 할당의 최소 단위입니다. 익스텐트 내 8개 페이지는 디스크에서 물리적으로 연속 배치가 보장되므로 Sequential Read가 가능합니다.
- "SQL Server에서 삭제와 수정은 즉시 디스크에 반영되지 않는다. 모든 것은 로그가 먼저고, 버퍼풀이 중간이며, 디스크는 마지막이다."
