## 상황 : 기존 테이블이 분리되어 사용될 예정.
ETL 영향도가 상당한 테이블.
테이블 A로만 사용하던 것을, 온라인 컬럼을 분리하여
테이블 A + 테이블 B 로 운영할 예정이며
테이블 B에는 기존에 테이블 A에서 쓰이던 컬럼들을 분리하여 가져감.

이때, 영향도 최소화를 위한 대응 방법은 뭘까?

DBA / DE로서 고를 수 있는 선택지 
A. 기존 job을 수정함(분리될 컬럼들을 load하지 않도록) + 분리된 테이블에서 일부 컬럼을 가져오는 새로운 ETL 잡 생성
B. ETL job 생성 없이 기존 job만 수정 : 컬럼별로 불러오는 테이블들을 별도로 지정하는 쿼리 생성
C. DB에서 분리된 테이블들을 관리하는 통합 VIEW를 생성하고 ETL에서는 VIEW를 참조하도록 수정

A는 공수가 C보다 많이들고, B는 추후에 다른 작업이 생긴다면 운영 복잡성이 있기 때문에 C를 선택하기로 하였다.


### STEP 
원본DB 분리 -> VIEW 생성-> ETL 기존 job에서는 view를 참조하도록 수정
